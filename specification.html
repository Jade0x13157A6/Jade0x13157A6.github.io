Making RISC-V specifications machine-readable.

An evidence-grounded workflow for extracting architectural parameters and normative constraints from natural-language RISC-V specification excerpts.

RISC-V specificationsLLMsYAMLPython validation

Challenge

RISC-V specifications combine configurable implementation choices with fixed architectural encodings and other mandatory requirements. An extraction process needs to preserve those distinctions rather than treating every mentioned number as a configurable parameter.

Method

The workflow uses a language model to extract items from a supplied excerpt and represent them in structured YAML. Each item is connected to source evidence and assigned one of three types.

  • Implementation parameter: an implementation-selectable value explicitly supported by the specification.
  • Architectural constant: a fixed value, width, or encoding defined by the architecture.
  • Non-parameter requirement: a constraint on behavior that is not a configurable value.

Reliability controls

The approach forbids inferred defaults or ranges that are absent from the input, preserves the distinction between limits and implemented counts, and validates the resulting catalogue with a Python script.
